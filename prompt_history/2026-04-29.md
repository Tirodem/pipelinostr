## Wizard install one-liner — sudo precedence fix

Diagnostic : `curl ... | bash` et `sudo curl ... | bash` ne lancent pas le wizard
(install.sh exit avec "Error: Run as root."). Seul `sudo su` puis `curl ... | bash`
fonctionne.

Cause : `sudo` ne s'applique qu'à la commande directement à sa droite. Avec
`sudo curl | bash`, c'est curl qui devient root, mais bash reste user.

Fix (option A retenue) : changer le one-liner partout en `curl ... | sudo bash`
(sudo s'applique à bash → install.sh tourne en root).

Modifications :
- `README.md:29` — one-liner mis à jour
- `scripts/install.sh:3,6` — header commentaires mis à jour + note explicative
  sur le piège `sudo curl | bash`

## Wizard `is_installed()` fix

Bug : install.sh clone le repo avant de lancer le wizard, donc `package.json`
existe toujours au démarrage du wizard → `is_installed()` renvoie true → branche
`existing_install` qui n'appelle jamais `write_config_file()` → `config/config.yml`
jamais créé.

Fix (option B retenue) : utiliser le fichier de service systemd comme marqueur
d'install terminée.

```bash
is_installed() {
    [ -f "/etc/systemd/system/${SERVICE_NAME}.service" ]
}
```

Le service systemd est l'artefact final écrit par `fresh_install()` — sa
présence est le marqueur le plus fiable.

## Build script — migrations copy fix

Bug : le service crash au démarrage avec
`ENOENT: no such file or directory, scandir '/opt/pipelinostr/dist/db/migrations'`.

Le runtime (`src/utils/paths.ts:25`) attend les SQL migrations dans
`dist/db/migrations/`. L'ancien build script (`tsc && cp -r src/db/migrations dist/db/`)
avait deux fragilités :
1. `cp -r` non-idempotent si le dossier de destination existe (copie *dedans*).
2. Le wizard appelle `npm run build >/dev/null 2>&1` → erreurs cp avalées.

Fix : remplacer la commande shell par un script Node cross-platform
(`scripts/copy-migrations.cjs`) qui purge + recrée + copie + fail-loud si pas
de .sql trouvé. Compatible dev Windows + prod Linux.

```
"build": "tsc && node scripts/copy-migrations.cjs"
```
