# Session 2025-12-25

## Session 1 - Migration NIP-17

### Contexte
Migration des DMs Nostr de NIP-04 (deprecated) vers NIP-17 (nouveau standard) tout en restant rétro-compatible.

Problème identifié : Amethyst ajoute un préfixe `[//]: # (nip18)\n` aux messages NIP-17, ce qui casse les commandes comme `/dpo`.

### Modifications effectuées

#### 1. crypto.ts - Support NIP-17 complet
- Import de `nip59` depuis nostr-tools pour unwrap
- Nouvelle interface `UnwrappedGiftWrap` avec sender réel, kind interne, content
- Nouvelle méthode `unwrapGiftWrap()` qui fait le flow complet Gift Wrap → Seal → Rumor
- Fonction helper `cleanAmethystPrefix()` pour nettoyer le préfixe NIP-18 d'Amethyst
- Nettoyage du préfixe appliqué dans `decryptEvent()` pour NIP-04 et NIP-44

#### 2. nostr-listener.ts - Réception NIP-17
- Pour kind 1059 (Gift Wrap), utilise `unwrapGiftWrap()` au lieu de `decryptEvent()`
- Extrait le vrai sender (de l'intérieur du rumor, pas le wrapper)
- Utilise le kind interne (14) au lieu du kind externe (1059)
- Le whitelist check se fait sur le vrai sender

#### 3. nostr.handler.ts - Émission NIP-17
- Import de `nip17` depuis nostr-tools
- Nouveau type `DmFormat = 'nip04' | 'nip17'`
- `NostrDmConfig` accepte `dm_format` optionnel par action
- `NostrHandlerOptions` accepte `dm_format` par défaut
- `sendDm()` dispatch vers `sendDmNip04()` ou `sendDmNip17()` selon config
- `sendDmNip17()` utilise `nip17.wrapEvent()` pour créer le Gift Wrap

#### 4. Configuration
- `config/config.yml.example` : ajout option `nostr.dm_format`
- `src/config/schema.ts` : ajout `dm_format?: 'nip04' | 'nip17'` au schéma
- `src/index.ts` : passage de `dm_format` aux handlers Nostr

### Comportement

#### Réception (double-écoute)
- Kind 4 (NIP-04) : déchiffré avec NIP-04, préfixe Amethyst nettoyé
- Kind 1059 (Gift Wrap/NIP-17) : unwrappé complètement, préfixe nettoyé, vrai sender extrait

#### Émission (configurable)
- `dm_format: "nip04"` (défaut) : kind 4, compatible tous clients
- `dm_format: "nip17"` : kind 1059 (Gift Wrap), meilleure confidentialité
- Peut être overridé par action dans le workflow

### Décisions techniques
- Utilisation des helpers natifs de nostr-tools (`nip59.unwrapEvent`, `nip17.wrapEvent`)
- Le nettoyage du préfixe Amethyst est fait partout (NIP-04 et NIP-17)
- Default à NIP-04 pour rétro-compatibilité

## Session 2 - Réponse dynamique NIP-04/NIP-17

### Problème
Les réponses en NIP-17 ne sont pas lisibles sur Primal (qui ne supporte que NIP-04).

### Solution
Répondre dans le même format que le message reçu :
- DM reçu en NIP-04 → réponse en NIP-04
- DM reçu en NIP-17 → réponse en NIP-17
- Trigger non-DM (zap, API) → utilise le format par défaut

### Modifications

#### Configuration
Nouvelle option `nostr.dm_reply_match_format` :
```yaml
nostr:
  dm_format: "nip04"           # Format par défaut (triggers non-DM)
  dm_reply_match_format: true  # Répondre dans le même format
```

#### Code
- `TriggerContext.dm_format` : stocke le format du DM reçu
- `workflow-matcher.ts` : définit `dm_format` basé sur `encryptionType`
- `nostr.handler.ts` : priorité action > trigger > default

### Priorité du format d'émission
1. Action-level override (`dm_format` dans le workflow)
2. Format du trigger (si `dm_reply_match_format: true`)
3. Format par défaut (`nostr.dm_format`)
